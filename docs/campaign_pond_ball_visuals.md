# 1~5스테이지의 62번 보드 재사용

Status: `NEEDS_PLAYTEST`

- 기존 62번의 통합 표면 광택·주변색 반사와 6점 시각 와핑을 재사용한다. 62번 설정 Resource를 공유하므로 이후 해당 광택/와핑 값 변경도 함께 반영된다.
- 2026-11-23 사용자 요청으로 아래→위 방향·세기 조절 발사, 비행 방향 중력, 옆벽 탄성 반사, 실제 충돌체 조준 가이드, 접촉 후 상향 중력, 천장과 하단 위험선을 함께 적용한다. 주인공 컷아웃도 62번의 1.17배/흰 외곽선 표시를 재사용한다. 적 순서·기존 얼음/분열/포식/거울 기믹·체력·합침·턴·피해 경로는 유지한다. 62번의 별도 적 일반공격 루프로 교체하지 않는다. 삭제한 외곽 합침 검사는 재도입하지 않는다.
- 레벨의 선택적 `board_visual_scene`을 기존 보드 설정 경로로 설치한다. 시각화는 적 기믹 핸들러와 독립적이라 적 교체 중 유지된다. 재설정/씬 종료 시 와핑과 반사 재질·접촉 콜백을 복원한다. 다른 레벨은 이 씬을 지정하지 않는다.
- 원본과 복구 방법: `backups/campaign_before_stage62_visuals_2026-11-22/README.md`.
- 관련 스크립트 4개 및 시각화 씬 Godot 문법 검사 통과. 5개 레벨은 백업과 비교해 시각화 참조와 load_steps만 추가했는지 확인한다. 전체 회귀·내보내기·실제 플레이 검증은 수행하지 않았다.
- 사용자 확인: 기존 투하/튜토리얼과 다음 공 활성화, 얼음 해제/적 전환 중 공 표시, 공이 쌓였을 때 성능.
- 후속 수정: 3·5번에서 추가 ext_resource가 sub_resource 뒤에 놓여 레벨 Resource 로드가 실패한 것을 수정했다. 외부 참조를 sub_resource 앞으로 이동한 뒤 1~5의 실제 Resource preload 문법 검사를 수행하여 오류 없이 통과했다. 메뉴 목록은 원래 등록을 유지한다.

## 발사 모드 추가 검증 (2026-11-23)

- 기존 DirectionalGravityLauncher를 그대로 설치하고 공 투하/합침 완료 시 상향 중력을 즉시 적용한다. 적 기믹 정리 후에도 하단 위험선과 발사 입력 소유권을 재적용한다.
- 거울 공 및 포식 반환 공은 선택적 보드 진입 위치 제공자를 사용하여 하단에서 등장한다. 기존 다른 보드에서는 원래 상단 위치를 유지한다.
- 1번 조작 안내와 반복 발사 문구를 레벨 데이터로 변경했다. 기본 안내는 다른 레벨에서 유지한다.
- 변경 스크립트 6개 문법 검사와 1~5 Resource preload 검사 통과. 실제 입력·반사·얼음/분열/포식/거울 연동·적 전환 및 성능은 사용자 플레이테스트가 필요하다.
- 표시만 적용된 중간 상태는 backups/campaign_before_stage62_launcher_2026-11-22/ 에 추가 저장했다. 최초 원본 백업은 그대로 유지한다.
- 거울방 진입 오류 후속: 사용자 실행 로그에서 `_refresh_overlay()`가 실행 중 보드에 없는 `get_ball_entry_position()`을 호출해 중단되는 것을 확인했다. 디스크의 보드에는 함수가 있어 실행 중 부분 재로드로 추정된다. 거울 미리보기/실제 출현 모두 API 존재를 검사하는 공통 helper로 변경하여 구버전 보드에서는 기존 상단 위치로 안전하게 처리한다. 완전 재실행 시 새 보드의 하단 위치 제공자를 사용한다. 관련 스크립트 2개 문법 및 거울방 Resource preload 검사 통과; 실제 진입 재확인은 필요하다.
