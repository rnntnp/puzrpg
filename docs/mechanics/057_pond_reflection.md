# 057 — 빛이 비치는 연못

상태: `NEEDS_PLAYTEST`. 사용자 요청으로 55번을 복제한 가벼운 반사광 시각 실험이다. 후보 생성은 생략했다.

## 행동 계약과 중복 확인

- 55번의 방향 발사, 옆 벽 반사, 접촉 후 위쪽 중력, 반사 가이드, 능력 편성, 위험선, 합성·콤보·피격·무한 체력을 그대로 재사용한다.
- 배경과 세 적은 55번과 같다. UI에 디버깅 문구를 추가하지 않는다.
- 기존 흰 반사광 스프라이트 대신 마스크 안에 절차적 반짝임과 색 번짐을 표시한다. 가까운 공 최대 3개의 색이 마주 보는 가장자리에 비치고, 푸른 연못 환경색이 넓게 비친다. 공 회전에도 광원과 이웃 방향은 월드 기준을 유지한다.
- 이는 실제 GI나 거울 반사가 아니다. 환경색은 배경 픽셀을 읽지 않는 설정값이며, 이웃 색은 공 데이터의 `glow_color`를 사용한다. 하트 공도 자신의 실루엣 마스크로 잘린다.
- 플레이어는 같은 색 또는 다른 색의 공을 가까이 두고 가장자리 색 변화를 비교한다. 반사는 피해·물리·합성 결과에 영향을 주지 않는다.
- 등록 중복은 55번과 의도적으로 동일하다. 새로운 의사결정 기믹으로 주장하지 않고 별도 시각 비교 스테이지로 등록한다. 적별 난이도나 공격 규칙을 추가하지 않는다.

## 비용과 재사용

- 스프라이트의 ShellOutline 알파 윤곽(임계값 0.2, 단순화 1.5px)을 삼각분할하고 각 삼각형을 두 번 세분한다. 콜라이더를 참조하지 않는다. 65×65 격자에서 실루엣 밖 높이를 0으로 두고 Poisson 식 laplacian(u)=−1을 SOR(1.7) 256회로 풀어 중앙 능선이 없는 볼록한 표면을 만든다. 높이는 z=0.18×이미지의 짧은 변×sqrt(u/max(u))다. 중앙차분으로 N=normalize(-dz/dx,-dz/dy,1)을 계산하여 메시 노멀과 128×128 선형 필터 노멀 텍스처에 저장한다. CanvasItem 셰이더는 텍스처 노멀을 픽셀마다 복원·정규화하며 광택 smoothstep(cos(12°+0.8°),cos(12°−0.8°),N·H)×1.0을 사용한다. 이웃 색은 아래 SG 모델로 계산하며 환경색에도 Schlick 프레넬을 사용한다. 실제 GI는 아니다.
- 전용 설정은 `pond_reflection_config.gd`, 핸들러는 55번 핸들러를 상속하고 전용 시각 레이어만 추가한다. Battle·MonsterActionController·공용 공 스크립트는 변경하지 않는다.
- 정지 상태에서는 초당 12회, 공 이동 중에는 실제 시간 기준 초당 30회 공간 격자로 가까운 공을 검색하고, 각 공의 셰이더에는 최대 3개만 전달한다. 공당 추가 MeshInstance2D 1개(약 1,136~1,632개 삼각형), 마스크·노멀 텍스처 샘플 각 1회이며 광선 추적·화면 복사·전역 블러·실시간 그림자가 없다. 실제 프레임 비용은 미측정이다.
- 미리보기에도 반사를 적용하되 미리보기는 다른 공의 광원이 되지 않는다. 합성 후 새 공은 다음 갱신에서 등록한다. 얼어 있는 공은 반사 레이어를 숨긴다.
- 합성·제거로 사라진 공은 기록을 정리한다. 핸들러 정리·장면 종료 시 추가 레이어를 제거하고 기존 반사광 표시를 복구한다. 적 전환 때는 보드와 효과를 유지한다.

## 검증 범위

새 스크립트·셰이더·레벨 로드, 목록 등록, 55번 재사용과 정리 경로만 확인한다. 광택이 내부 캐릭터를 가리지 않는지, 다른 색 공 옆에서 번짐이 읽히는지, 많은 공이 쌓였을 때 성능이 유지되는지는 사용자 플레이테스트가 필요하다.

## 메시 생성과 검증

- 11단계 메시를 resources/visuals/pond_meshes/ball_01.res~ball_11.res에 미리 저장한다. 플레이 중에는 리소스를 공유해 읽기만 하며 윤곽 추출·삼각분할·노멀 생성은 하지 않는다. 재생성은 Godot --headless --path . --script tools/generate_pond_meshes.gd로 수행한다.
- 11개 메시의 삼각형 중심이 실제 알파 윤곽 안에 있는지, 노멀 길이가 1인지, 같은 실루엣 메시 캐시가 재사용되는지 확인했다. 전체는 14,480개 삼각형이다. 화면 품질·프레임 성능은 아직 미측정이다.

## 현재 반사 모델

- SG 방향 로브는 G(R,L)=exp(λ(dot(R,L)−1)), R=reflect(−V,N)이다. 이웃 반지름 a와 중심 거리 d로 c=sqrt(1−(a/d)²), λ=clamp(ln(2)/(1−c+0.08²),2,128)을 계산한다. 큰·가까운 공은 넓게, 작은·먼 공은 좁게 비친다.
- 이웃 세기는 w=clamp(8(1−c),0,1)×[1−smoothstep(0.65×180,180,표면 간 거리)]이다. 입체각을 사용하지만 앞의 8은 미술 보정이다.
- 프레넬 F=0.04+0.96(1−clamp(N·V,0,1))⁵. 각 이웃 반사는 색×w×G×max(N·L,0)×F×0.60×18으로 계산하고 합산한다. 18은 그림 위 반사 레이어의 노출 보정이며 물리적 에너지 보존을 주장하지 않는다. L의 z=0.35는 2D 보드의 가상 깊이다. SG 적분이나 실제 이웃 형상 반사·가려짐·다중 반사·굴절은 계산하지 않는다.
- 참고: [MJP의 Spherical Gaussians 101](https://therealmjp.github.io/posts/sg-series-part-2-spherical-gaussians-101/), [Google Filament의 Fresnel 설명](https://google.github.io/filament/Filament.md.html). 모델과 보정 수치는 위와 같이 제한적으로 재사용했다.
- 광택 크기(12°)와 가장자리 전이 폭(0.8°)을 분리해 넓은 흰 중심과 얇은 경계를 만든다. 주변 반사가 너무 약하다는 사용자 피드백에 따라 반사 강도 0.70→1.0, 노출 6→18로 바꿔 기존 대비 약 4.29배 강화했다. SG·입체각·프레넬 모델과 갱신 수는 유지한다.

- 주변 반사 강도는 직전 버전의 60%(1.0→0.60)로 낮췄다. 발사 시 새 공의 메시를 바로 등록하고, 착지 여부와 무관하게 이동 중 30Hz로 발사 공과 주변 공의 반사를 갱신한다. 합성 히트스톱에도 갱신 주기가 늘어지지 않도록 실제 시간을 사용한다. 광택 강도·크기는 유지한다.

- 꺾인 광택 피드백에 따라 최근접 윤곽 거리 기반 표면을 Poisson 표면으로 바꾸고 삼각형 보간 대신 픽셀 노멀 텍스처를 사용한다. 노멀 텍스처도 미리 저장하며 플레이 중 블러·표면 생성이나 삼각형 증가가 없다. 광택 크기·경계 폭과 주변 반사 강도는 유지한다.

- 흰 광택은 두 방향을 사용한다. 주 광택은 12°·강도 1.0, 보조 광택은 주 방향에서 180° 반대·8°·강도 0.75다. 두 광택은 1−(1−H1)(1−H2)로 합성한다. 보조 각도·크기·강도는 전용 설정에서 조절한다. 표면 모양에 따라 각 광택이 갈라질 수 있으므로 화면상의 흰 영역 수를 강제로 둘로 제한하지 않는다.

- 가장자리 광택 요청에 따라 메시 최대 높이를 이미지 짧은 변의 30%→18%로 낮췄다. 같은 광택 노멀 각도를 더 바깥에서 만나도록 표면을 납작하게 하고 11단계 메시·노멀맵을 함께 재생성했다. 바깥 윤곽과 두 광원 방향·광택 크기는 유지한다.

- 8단계만 표면 깊이 비율을 0.18→0.15로 낮춰 광택을 조금 더 가장자리로 옮기고, 두 광택의 각도 반지름을 80%(12°→9.6°, 8°→6.4°)로 줄였다. 다른 단계 수치는 유지한다.

- 두 메인 광택에 더해 약한 환경 조명 3개를 추가했다. 위쪽 푸른빛(0.16), 오른쪽 따뜻한빛(0.10), 왼쪽 보랏빛(0.12)이며 전용 설정의 색 알파가 강도다. 환경 반사는 SG 지수 6의 넓은 로브와 약한 N·L 채움을 합성한다. 실시간 Light2D나 그림자·화면 복사는 추가하지 않고 기존 표면 셰이더에 계산만 추가한다. 환경 방향은 메시 로컬 좌표로 변환해 공이 돌아도 월드 방향을 유지한다.

- 2026-10-06: 비교 요청으로 물방울 표면 적용 직전의 두 광택·주변 반사 강도 0.60을 복원했다. 물방울 셰이딩은 58번으로 분리했다.
