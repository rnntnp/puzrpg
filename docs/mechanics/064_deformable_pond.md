# 64. 소프트바디 연못

상태: `NEEDS_PLAYTEST`

## 목적·중복 확인

사용자가 요청한 62번의 실제 소프트바디 비교판이다. 새 전투 기믹을 만들지 않고 60번 QuarkPhysics와 기존 방향 발사·합성·적 순서를 재사용한다. 60·61번과 물리 방식은 의도적으로 겹치며 62번의 시각 와핑과 직접 비교하는 용도다. 기존 등록은 63번까지 있으므로 64번으로 등록한다.

## 동작 계약

- 아래에서 방향을 정해 발사한다. 옆 벽 반사와 접촉 후 상향 중력 전환은 기존 방향 발사와 같다.
- 각 공의 외곽 입자 16개와 스프링을 QuarkPhysics로 적분한다. 눌린 입자 외곽 자체가 다른 공·벽과 충돌하고 같은 입자 위치를 그림과 가이드 쿼리에도 전달한다. Godot 강체 접촉과 이중으로 밀어내지 않는다.
- 일반 공은 원래 충돌 도형의 외곽에서 입자를 뽑고, 하트/별은 실제 shell mask의 오목 윤곽을 따른다. 찢김·자기 충돌은 이번 범위가 아니다. Godot 가이드 쿼리는 볼록 근사다.
- 같은 단계의 실제 소프트 접촉은 기존 합성 요청으로 전달한다. 최초 착지 알림을 합성보다 먼저 보낸다. 최대 단계·잠금·예약·점수·피해·콤보·게이지·Break·Danger Line 판단은 기존 경로를 따른다. 62번의 1.28배 시각 합성 후보 검사와 접촉 모양 보정은 사용하지 않는다.
- 몸체의 모양 복원과 면적 제약은 물리 계산의 일부다. 62번의 추가 중앙 와핑·접촉 보간 슬라이더를 이 물리에 적용하지 않는다.
- 기존 테스트처럼 양측 체력은 무한이다. 같은 적 3명과 기존 공격 간격·장비 효과·보드 유지 규칙을 사용한다. 물리 비교가 목적이므로 Teach/Twist/Boss에 새 규칙을 추가하지 않는다.
- 원본 컷아웃 주인공, 62번 반사 설정, 분리된 표정 레이어(기본 변형 15%)를 재사용한다. `실제 충돌체 표시` 체크박스로 현재 물리 외곽·입자를 표시한다.
- Quark 확장이 없는 환경에서는 기존 6입자 XPBD 실제 소프트 솔버로 대체하고 화면에 명시한다. 강체+그림 와핑으로 대체하지 않는다.
- 적 전환 때 보드는 유지한다. 최종 종료·패배·재시작·장면 이탈·핸들러 교체 시 임시 입자 월드·쿼리 도형·메시·표정 레이어를 제거하고 원래 충돌 도형·적분·마스크·CCD·재질을 복원한다.

## 구현·튜닝

- 후속 두께 수정(2026-11-24 사용자 피드백): 변형 Jacobian을 그대로 따라가면 압축 구간에서 생성 선폭도 줄어들므로 64번의 생성 선폭은 `BallVisual.outline_screen_width`/`inner_white_screen_width`의 화면 픽셀 폭으로 고정했다(현재 색 4px+흰 2px). 경계 거리/법선 및 가림 깊이 탐색은 유지하되, 탐색 반경·색/흰 밴드 폭에 변형 배율을 곱하지 않는다. 가림 fade는 알파만 조절한다. 두 모양에서 fixed 모드 true/폭 (4,6) 전달 확인, 셰이더 오류 없음. 이전 Jacobian 모드는 64번의 기본 선폭 계산에서 사용하지 않는다.

- 가림 경계 두께/시작점 보정(2026-11-24): 64번은 source texel 폭을 단순 node scale로 곱하던 대신 UV 미분의 역 Jacobian과 잘린 경계 법선으로 screen 폭을 구한다. vertex 확대/회전/실제 변형을 포함하므로 일반 자세에서 원래 색 4px+흰 2px와 같은 폭이 된다. 실제 fixture에서 원본 색 폭 4px/동일 texel 입력/metric 활성화를 확인했다.
- 잘린 경계의 가장 가까운 위치를 먼저 찾고 gradient로 법선을 보정한 뒤 색/흰 밴드/가림 깊이에 동일 기준을 쓴다. 숨겨진 깊이는 그 경계부터 첫 이탈 지점까지 순차 탐색 후 세분한다. 하트·별의 오목한 간격을 건너뛰던 전체 구간 이분 탐색과 방향별 서로 다른 fade를 대체했다. 깊이 기준 3배·fade 구간 0.5폭은 유지하며, fade는 두께가 아닌 알파에 한 번만 적용한다. 원래 색 테두리 위 흰색 방지/앞 공 위 seam 방지도 유지한다. 공용 include의 기본 경로는 legacy로 두고 64번만 metric 모드를 켜므로 62번 동작은 유지한다.
- scoped 검증: 겹침 정지 및 전단/압축 변형 fixture 캡처, 가림 OFF/ON 재연결, 3+3→4 합성/다음 입력, 2개 스크립트 문법 및 runtime shader 오류 없음. 실제 체감 두께/연결부 자연스러움은 사용자 비교 대상이다.

- 발광/합성 이펙트 GPU 전환(2026-11-24 사용자 요청): 공용 `BallGlow`는 원 12개를 CPU에서 만드는 `_draw`를 제거하고 공유 QuadMesh+ShaderMaterial 하나를 참조한다. 공별 색/강도는 modulate로 전달하며 원형 공간 감쇠는 fragment shader에서 계산한다(4개 정점의 보간만으로 원형 감쇠를 만들 수 없음). 기존 12겹 밝기 프로파일을 매끄러운 적분 근사로 유지한다. 공용 발광은 다른 단계에도 적용된다.
- 64번 합성 이펙트는 `deformable_pond_bursts` 단일 MultiMeshInstance2D/공유 quad/SDF shader로 처리한다. 링·광선·끝점 원·마름모를 인스턴스로 묶고, 생성 시 2D 변환/색/시작 시각/수명/종류/크기를 기록한다. 프레임마다 개별 도형을 재구성하지 않고 GPU vertex에서 이동·크기·fade, fragment에서 AA 도형을 계산한다. 버퍼는 생성이 있는 프레임에 한 번 업로드한다. 수명은 기존과 같은 scaled delta clock/quad ease-out을 사용해 hit-stop을 따른다. 128개 primitive 슬롯/효과, 기본 효과 슬롯 64개(`burst_initial_capacity`), 부족하면 2배 확장하며 만료 후 재사용한다. 입장 시 투명/offscreen 인스턴스로 2프레임 예열한다.
- MergeGame에는 기본 연출을 유지하는 선택적 `merge_burst_renderer` Callable만 추가했고 64번이 등록/해제한다. 다른 단계 합성 효과는 기존 경로다. 색/크기/레이 수/링 조건/수명/무작위 소비는 기존 공식에 맞췄고 GPU SDF 모서리/발광 프로파일은 근사다.
- scoped 검증: 전용/공통 5개 스크립트 문법, 실제 3+3→4/다음 입력, shader 오류 없음. 이펙트 중간 진행률 캡처에서 링/광선/끝점 모양과 위치 확인. 만료 후 active 0/64개 슬롯 반환/visible 0, 70개 동시 효과에서 128 슬롯으로 확장·모두 반환 확인. 단일 실행에서는 28개 합성 이펙트를 버퍼 업로드 6번으로 처리했다(진단 예열 추가 전 수치).
- 같은 가림 ON/40개/20쌍 요청 3회: 연쇄 포함 각 28회. 실제 최악 프레임 간격 27.50/17.90/18.75ms, profiler 내부 최악 34.14/24.42/17.95ms, 평균 profiler FPS 487.8/472.4/487.9. 이전 완성 공 풀 적용 시 실제 최악은 49.14/33.74/28.70ms였으나 연쇄 합성 횟수가 달라 정확한 동일 상태 비율로 해석하지 않는다. 기존 MergeBurstEffect/BallGlow `_draw`는 64번 측정 경로에서 제거됐고 새 피크는 일반 물리 갱신/결과 공 배치다. 결과 `.mcp/godot-runtime/soft64_instanced_effects_burst.json`.

- 중복 제거/완성 공 풀링(2026-11-24 사용자 요청): 얼굴 분리 셰이더를 원본 코드별 공유 캐시로 변경했다. 64번 native 등록은 전용 state 준비 경로를 사용해 임시 6입자 XPBD 배열/바인딩을 만들고 버리는 중복을 제거한다. 다른 Quark 단계는 기존 기본 준비 경로를 유지한다.
- 64번 전용 `deformable_pond_pool`이 공 노드+전체 비주얼/얼굴+변형 메시+쿼리 도형+native 16입자/스프링을 단계별로 보관한다. 목표 예비 4개/단계, 보관 상한 8개/단계이며 설정 Resource에서 조절한다. 예비는 렌더 프레임마다 1개씩 준비한다. 최초 준비 비용이 없어지는 것이 아니라 입장/유휴 프레임으로 분산되며 풀 고갈 시 기존 생성 경로를 사용한다. 메모리는 예비 완성 개체만큼 추가 사용한다.
- `MergeGame`에는 종류별 분기 대신 선택적 acquire/release Callable만 추가했다. 비활성 개체는 트리에 남겨 재등록 비용을 피하되 숨김/처리 중단/충돌 비활성/merge_locked/pool_inactive 처리하고 `get_active_balls`와 방향 발사 목록에서 제외한다. native 월드 목록에서도 제거하므로 대기 입자는 솔브하지 않는다. active snapshot 진단에서 활성 공 9개, 예비 70개일 때 native world는 벽 4개+활성 9개만 포함했다.
- 재사용 시 착지/합성잠금/외부 토큰/힘/회전/방향 비행 메타데이터/신호 연결/입자 위치·이전 위치/속도·접촉 캐시를 초기화한다. 세대 번호로 이전 CCD 지연 콜백을 무효화한다. 마킹/상태 효과가 남은 합성 소스는 기존 제거 경로를 사용해 지연 시각 콜백이 다음 활성화에 섞이지 않게 한다. 일반 공 설정이 바뀌지 않는 동일 단계별 완성 개체만 재사용한다. 핸들러 종료 시 provider를 해제하고 예비 native/시각 리소스를 정리한다.
- Scoped 검증: 동일 ball ID/native ID 재사용, 착지·힘·토큰·flight/lock/inactive 초기화 true, merge 신호 연결 1개 확인. 실제 하트 3+3→4 합성 및 다음 입력 true. 보드 전체 제거 후 활성 0개/native world 4개(벽만), 씬 재진입과 전용 스크립트 문법 통과, 최종 오류 로그 없음.
- 같은 40개/20쌍 동시 합성·가림 ON·반복 1/소구간 2 시험 3회: 실제 프레임 간격 최악 49.14/33.74/28.70ms, profiler 내부 최악 56.38/41.01/30.63ms. 이전 공유 가림만 적용한 시험의 실제 최악은 102.10/54.25/50.00ms였다. 이번 연쇄 합성은 26/27/31회로 결과 수가 달라 평균 FPS의 직접 성능비 비교는 하지 않는다. 마지막 시험은 초기 40개 중 1개와 합성 결과 31개 모두 풀에서 획득했다(hits 32, 초기 생성 miss 39). 최악 항목에서 얼굴 shader 구성/native 신규 등록 피크가 빠지고 효과 draw/일반 물리/풀 반환이 남았다. 합성 파티클·소리·미리보기는 이번 완성 공 풀의 대상이 아니다. 결과 `.mcp/godot-runtime/soft64_complete_ball_pool_burst.json`.

- 공유 가림 패스 재측정(2026-11-24 사용자 요청): 새 profiling 프로세스에서 같은 40개/20쌍 동시 합성 fixture를 3회 반복했다. 각 회의 profiler 최악 frameMs는 64.93/49.47/46.66ms, 별도 6초 process_frame wall interval 최악은 102.10/54.25/50.00ms였다. 평균 profiler FPS는 357.4/417.1/405.6, 실제 합성은 연쇄 포함 27/28/28회였다. 첫 실행의 긴 실제 간격은 여전히 남아 있으므로 엔진 내부 측정만으로 끊김 해결을 주장하지 않는다. 첫 실행 최악 내부 프레임에는 native 등록 12회 19.94ms(얼굴 분리 14.98ms 포함), 반복 실행 최악에는 합성 공 생성 20회 약 12.4~12.7ms가 관찰됐다. 결과는 `.mcp/godot-runtime/soft64_shared_prepass_repeated_burst.json`. 측정 후 일반 실행으로 복원했다.

- 가림 패스 생성 비용 수정(2026-11-24): 현재 CanvasItem 경로는 하드웨어 depth test로 전환하지 않았다. 가림 판정은 기존처럼 GPU ownership prepass/fragment 비교로 한다. 64번은 복잡한 shell shader를 공마다 문자열 가공해 마스크 shader를 만드는 대신 전용 `deformable_pond_ownership.gdshader` 하나를 공유한다. 기존 변형 메시를 그대로 참조하고, 합성 소스의 마스크 node/material을 결과 공에 재사용한다(대기 풀 최대 64). 62번은 기본 factory/release hook의 기존 동작을 유지한다.
- 동일한 40개/동시 20쌍 부하에서 추가 마스크 할당 없이 총 할당 40개 유지, 재사용 21회, 활성 mask shader 1개 확인. 연쇄 포함 합성은 이 실행에서 27회/종료 13개였다. profiler 평균 319.4 FPS/최악 내부 frame 71.33ms였고, 별도 wall interval 최악은 110.65ms여서 전체 프레임 끊김 해결로 해석하지 않는다. native 새 공 등록/표정 분리와 효과 생성 비용은 남는다. 최종 정지 겹침 캡처/오류 로그 확인, 전용/공통 스크립트 scoped 문법 통과.

- 가림 전체 토글(2026-11-24 사용자 요청): 외곽선 전용 체크박스를 제거하고 `공 가림 켜짐/꺼짐` toggle Button 하나로 통합했다. 외곽선은 가림 상태를 따른다. OFF에서는 재질 원본을 복원하고 ownership mask를 제거하고 SubViewport 갱신을 중단한다. ON/OFF/ON 재생성 검사 통과(OFF mask/material 0, viewport disabled). 기존 실제 충돌체 표시 체크박스는 유지한다.
- 급격한 합성 부하 측정: 소구간 2/반복 1, 현재 변형 제한/내부 감쇠 유지, 720×1280/VSync 끔/프로파일링. 40개를 준비하고 20쌍을 같은 프레임에 기존 합성 요청 경로로 발생시켰다(접촉 발생 자체를 기다리는 일반 플레이가 아닌 강제 부하 fixture). 기존 hit-stop/생성/파티클/밀어내기/공격은 유지. 두 조건 모두 연쇄 포함 합성 26회, 종료 14개였다.

변형 제한 15→10%, soft/hard 반경 비율 1.05/1.10, rigidity 0.45/shape matching 0.20/area rigidity 0.85로 조정했다. 화면 구석 가림 토글 아래에 생성 외곽선 두께 0~7px 슬라이더(기본 6px, 0.25px 간격)를 추가했다. 색:흰색 비율은 유지하고 0에서는 생성 테두리와 거리장 갱신만 끄며 소유권 가림은 유지한다. 상한은 현재 거리장 범위 7.5px 안에 AA까지 들어가도록 정했다. 원래 스프라이트의 외곽선은 별도다. 변경 리소스/스크립트 런타임 로드 및 오류 없음 확인.

### 변형 한도 실시간 슬라이더 (2026-11-25)

화면 구석 y=180에 변형 한도 1~25% 슬라이더를 추가했다(기본 10%). 입자 변형 상한과 soft/hard centroid 반경 제한을 함께 갱신하고, 활성 native body의 탐색 반경도 갱신 후 wake한다. rigidity/shape matching은 탱탱한 설정으로 유지한다. solver 설정은 configure 시 duplicate해 원본 Resource에 조작값이 남지 않는다. 슬라이더 5→20→10%의 물리 설정 반영과 공유 기본값 10% 유지, 런타임 오류 없음 확인. 0은 native API에서 제한 해제를 의미하므로 범위에서 제외했다.

### 물리 외곽 여유 추가 (2026-11-25)

사용자 요청으로 collision_padding_px=10을 64번 전용 설정에 추가했다. native rest chain에 화면 px를 world 단위로 변환한 polygon offset을 적용하고 16입자로 단순화한다. 렌더는 current-rest 변위만 받으므로 기본 스프라이트 크기는 유지한다. native 충돌, query hull, 측벽 반사, debug chain 및 centroid 검색 반경은 모두 확장된 rest chain에서 파생된다. 풀 재사용도 같은 chain을 유지한다. 두 공 각각 여유가 있으므로 원래 물리 외곽 사이 간격은 약 20px 늘 수 있다. 16입자 근사로 정확한 균일 10px Minkowski 외곽은 아니다(검사한 원/하트 축별 확대 약 9.3~10px, 별 일부 축 6.2~10px).

하트 2회 발사→4단계 합성→다음 입력, 리소스/스크립트 런타임 오류 없음 확인. 기존 스프라이트 외곽과의 오차에 10px를 정확히 더한 보장은 아니며, 기존 물리 경계에 추가한 여유다. 실제 외곽 간격과 체감은 사용자 플레이로 조정한다.

### 전체 단계 색 테두리 기준 충돌 외곽 교정 (2026-11-25)

사용자가 5번 공의 과한 크기를 보고해 11종을 전수 비교했다. 기존 catalog 충돌 외곽+5px는 5번의 색 테두리보다 좌우 약 9.18px씩 컸고 9~11번 좌우는 약 14~16.5px까지 컸다. 64번 전체 공을 ShellOutline alpha contour에서 추출하고, shader의 outline_expand_texels에 따른 vertex 확장까지 동일하게 반영했다. 추가 collision_padding_px는 0으로 설정한다. 62번/campaign collider는 변경하지 않는다.

16개 native 입자는 유지하되 좌우상하 극점을 보존하고 가장 큰 윤곽 오차 구간을 우선 분할하도록 fitting을 개선했다. 128점 reference 대비 rest chain 축 극점 오차는 6번 별 0.36px 이내, 나머지 0.001px 이내였다. 곡선 중간의 최대 reference→chain 거리 오차는 5번 1.65px, 전체 0.92~4.01px로 완전히 일치하는 것은 아니다. 11종 색 외곽/충돌체 중첩 캡처를 collider_shell_fit_all.png에 저장했다. 실제 하트 2회 발사→4단계 합성→다음 입력, 런타임 오류 없음 확인. 캡처는 rest 상태이며 변형 중 스프라이트와 물리 경계의 추가 차이는 남을 수 있다.

### 고정 설정 및 캠페인 재사용 (2026-11-25)

사용자 요청 최종값: 변형 한도 7%(슬라이더 제거), shell 색 외곽 기준 padding +4px, 생성 cut border 총 3px(색 2px/흰 1px, 슬라이더 제거), 가림 기본 켜짐. campaign_pond_ball_visuals는 같은 solver/occlusion/풀/효과를 조합해 1~5에도 적용하며 적 handler를 교체하지 않는다. 캠페인에는 debug HUD를 표시하지 않는다. 자세한 범위 검증은 docs/campaign_pond_ball_visuals.md를 참조한다.
